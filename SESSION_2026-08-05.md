### 2. Multi-engine calendar with per-calendar type picker
Each sub-calendar remembers its own view engine. Selecting a calendar reveals a **"Calendar type:"** picker (Classic / DayFlow / Full Calendar / Scheduler / iLamy).

- `useCalendars` gained an `engine` field (persisted in localStorage, backfilled for old data)
- Shared `CalendarEngineProps` contract (`src/components/calendar/engines/types.ts`)
- Lazy-loaded engine registry (`src/components/calendar/engines/index.tsx`) — each engine is code-split, only loads when selected
- All engines share the app's event data and are wired to `/api/calendar` (create/update/delete)
- Picker UI + engine dispatch added to `src/app/(app)/calendar/page.tsx`

## Testing notes (for future sessions)
- **Playwright auth quirk:** the login form submit can fail via browser automation (client CSP/hydration), but backend auth is fine. Workaround: do a `curl` credentials login to get a session cookie, then inject it into the Playwright context (parse `#HttpOnly_` lines in the Netscape cookie jar).
- **`networkidle` times out** on the calendar page (live clock keeps a connection open) — use `waitUntil: "domcontentloaded"` + explicit waits.
- Dev-server cold-compiles a route on first hit (~5s for `/api/rpg`); warm it before asserting.
- No test framework is configured; verification is build + typecheck + Playwright screenshots.
